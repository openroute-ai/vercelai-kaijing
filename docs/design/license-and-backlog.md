## 3. M1 到 M6

顺序不要倒。每一阶段都要能在上一阶段的数据上演示，而不是平行做一套假数据。

| 阶段 | 做什么 | 完成时能看到 |
| --- | --- | --- |
| M1 领域 | 在工作台 SQLite 增加 [domain.md](domain.md) 的 `drama_*` 表。`packages/drama-core` 补上校验和 JSON 解析的测试。短剧面板能手写一稿剧本和一版分镜并重新打开 | 不调用模型，关掉网关，数据仍在 |
| M2 导演 | 实现 `drama.rewrite_script`、`extract_entities`、`breakdown_storyboard`、`write_prompts` 的文本路径，以及「做一集」停在提示词就绪。MCP 暴露同名工具。导演技能用开镜自己的文字 | 一段输入得到可编辑的剧本和分镜表。此阶段可以先用测试桩代替真实文本模型 |
| M3 画布 | `drama.sync_canvas`、`drama.update_shot`、`@` 选择。生成前就能在画布上看到剧本、角色和镜头卡 | 改分镜后节点和引用更新，坐标不被重置 |
| M4 网关 | 真实的图像和视频适配器、登录后的生成接口、预扣和失败回退、本机代理下载成素材。角色图和镜头视频命令接上 | 不配置供应商 Key，用云端账户能出一镜视频。失败会退回积分 |
| M5 成片 | `drama.assemble_episode` 把就绪镜头放进现有时间线，写字幕，导出 MP4 | 本机得到可播放文件。云端没有这份 MP4 |
| M6 交付 | Windows 和 macOS 安装包、签名和公证、自动更新、官网下载页 | 未参与开发的人：安装 → 登录 → 一句话 → 导出 |

M6 是一期的完成定义。只做完 M2 的开发态不算一期结束。

M2 若还没有真实文本供应商，允许用夹具模型把固定 JSON 解成领域对象，但命令名、表和面板必须是真的。M4 之前不要让「做一集」按钮假装已经出片。

## 4. 明确不做

一期不做：

- 完整浏览器 SaaS：项目、画布和成片都在云端多人协作
- Android 客户端
- Toonflow 的 3D 白模预演、插件市场、全套多语言
- 把 Vue 界面拼进这个 React 仓库
- 把画布改写成 Next.js App Router
- 复制火宝短剧的任何代码或提示词原文
- 要求普通用户自己部署或自己准备全套供应商密钥
- 在云端保存成片作为默认路径
- 让平台运营编辑用户的本机项目

二期才重新考虑浏览器工作台和手机瘦客户端。届时工作台仍应是 Vite 前端，而不是把现有画布改成 App Router。

## 5. 实现时的检查

合入 M1 及以后的改动前，对照下面几条：

- 新的写路径是不是短剧命令或现有命令内核，而不是组件里直接改库
- 供应商密钥是不是只出现在 API 进程
- `apps/web` 有没有新增「打开某个项目画布」的页面
- diff 里有没有 Vue 单文件组件，或从火宝仓库来的文件
- 用户看得见的字符串是不是开镜，而不是上游产品名
- 积分变动有没有对应的 `credit_ledger` 行
