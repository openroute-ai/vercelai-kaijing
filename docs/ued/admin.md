# 平台运营后台

运营人员使用 `apps/web`，开发期 http://localhost:30051 。这是另一份 better-auth：cookie 前缀 `web`，数据在 `web_auth`。桌面的 `cloud.session_token` 进不了这里，这里的 cookie 也进不了 `/cloud-account`。

后台管账户、邀请、积分和生成任务。它不打开用户的画布、短剧稿、时间线或本机成片，也没有项目 id 的编辑器。

## 1. 登录

入口是登录页，文案标明「平台运营」，不是开镜桌面注册。

主路径是邮箱和密码，走 better-auth 的邮箱登录。受邀手机号走现有手机号验证码，验证通过后由 better-auth 的手机号插件建立运营用户。公开的邮箱注册页关闭：访问注册地址时回到登录，不出现注册表单。`/sign-up` 由 better-auth 门禁拒绝，界面不把它包装成「暂不开放，请填资料」。

| 状态 | 界面 |
| --- | --- |
| 空 | 邮箱、密码。主按钮「登录」 |
| 提交中 | 按钮不可重复点 |
| 成功 | 进入「薄云总览」 |
| 失败 | 留在登录页。不提示这是桌面账户或运营账户，避免拿桌面邮箱来试运营密码时泄露身份 |
| 没有权限 | 独立的无权限页，主按钮「返回登录」 |

找回密码沿用现有页面，只对运营这套 better-auth 发信。邮件里的链接打开运营后台，不打开桌面工作台。

登录页不放「下载开镜」作为主按钮。需要的话用页脚文字链去 vercelai.cn，避免运营误以为自己在注册桌面用户。

## 2. 外壳

侧栏分组与现在的导航一致：

| 组 | 项 | 路径 |
| --- | --- | --- |
| 总览 | 薄云总览 | `/console` |
| 账户 | 用户、邀请 | `/console/users`、`/console/invitations` |
| 薄云 | 积分、生成任务 | `/console/credits`、`/console/generation-jobs` |
| 设置 | 账号设置，以及标成稍后的日志、公告、角色 | `/settings` 及子页 |

顶栏身份是运营用户自己的名字，菜单「账号设置」「退出」。退出只清 `web` 会话。

总览页标题「薄云总览」，说明保持现在这句：云端只保存账户、积分和生成任务元数据，短剧项目、画布和成片留在桌面。两张卡：积分账户数量、生成任务数量。主操作「查看列表」。加载时数字为「…」。失败时数字为「—」，卡内显示错误，不编一个 0。

侧栏里没有「项目」「画布」「短剧」「成片」。以后也不要加。

## 3. 用户

列表是云端账户，不是本机项目成员。列：身份、状态、注册时间。主操作「详情」。筛选：搜索、全部 / 正常 / 已封禁。分页沿用现有列表，不一次拉出全部用户。

详情页展示账户字段和封禁。封禁的确认：「封禁后，对方不能再用这个云端账户生成。对方电脑上的项目不会删除。」主按钮「封禁」，次按钮「取消」。解封是次操作。

详情页不显示剧本、分镜、画布缩略图、本机路径或 MP4。没有「以该用户身份打开开镜」。

| 状态 | 界面 |
| --- | --- |
| 加载 | 表头在，行内「正在加载」 |
| 空 | 「还没有云端用户。」 |
| 失败 | 行内错误和「重试」 |
| 封禁成功 | 状态变为已封禁，列表徽章更新 |

## 4. 邀请

邀请是加入平台运营，不是加入某个短剧项目。页上的说明就写这一点，避免运营以为邀请会共享用户的画布。

字段沿用现有能力：手机号、邮箱，或两者。主按钮「发送邀请」。只填手机号时，对方用该号码在运营登录里收验证码，由 better-auth 完成注册并加入。只填邮箱时发邀请邮件。

| 状态 | 界面 |
| --- | --- |
| 空列表 | 「还没有邀请。」主按钮仍可发送 |
| 发送中 | 按钮不可重复点 |
| 成功 | 新行出现在列表，状态为待接受 |
| 失败 | 表单保留，说明原因（邮箱无效、手机号无效、已是成员） |

接受邀请的页面在运营域名下。接受成功进入薄云总览。接受失败回到说明，不把人带到桌面 `/cloud-account`。

## 5. 积分

标题「积分」。说明：这里看余额和流水。桌面用户不能在自己的电脑上改这个数。

两张表：账户（用户、余额、更新时间）、流水（时间、用户、变动、原因、备注）。原因只用已有的 `grant`、`hold`、`capture`、`release`、`adjust`。

调整余额是主操作，放在账户行上，不放在桌面。表单：金额、原因（发放 `grant` 或调整 `adjust`）、备注。备注必填。主按钮「记入流水」。

| 状态 | 界面 |
| --- | --- |
| 空 | 「还没有积分账户。」M1 时期这是正常的，不画成故障 |
| 加载 | 数字和表用「…」 |
| 成功 | 余额和流水同时更新 |
| 失败 | 对话框不关，显示错误，不改本地显示的余额 |

流水只读。不能删除一条 `hold` 来「退款」。退回由生成失败的 `release` 产生，运营在表里能看到。

## 6. 生成任务

列表服务排障：状态、供应商、种类（文本 / 图像 / 视频）、错误信息、积分花费、时间。点进详情可以看到 `prompt` 和请求里的排障字段。

详情不是剧本编辑器。不提供保存、改分镜、重跑成片或下载用户本机 MP4。若结果只是一块短期地址，页面注明「地址会过期，成片以用户电脑上的文件为准」。没有本机路径。

| 状态 | 界面 |
| --- | --- |
| 空 | 「还没有生成任务。」 |
| 加载 | 表内加载 |
| 失败 | 「任务列表没有载入。」「重试」 |
| 任务失败 | 行内状态「失败」，详情给出错误信息。不出现「打开画布」 |

M4 之前任务可能停在排队。列表如实显示排队，不把排队画成成功。

## 7. 设置里标成稍后的项

操作日志、系统公告、角色权限若仍标成稍后，侧栏保持不可用或进入说明页，不做成空表格假装已经审计了短剧。账号设置只改运营自己的密码和资料，不绑定某台桌面的项目。

## 8. 运营误打开桌面时

若运营在浏览器里打开 http://127.0.0.1:3020 ，那是开镜工作台，要用云端账户，不能用刚才的运营登录。工作台不识别 `web` cookie。不要在运营后台加「切换到用户画布」。
